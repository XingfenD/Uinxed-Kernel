# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build Commands

```bash
make              # Build kernel (UxImage) and bootable ISO (Uinxed-x64.iso)
make run          # Build and run in QEMU (qemu-system-x86_64, q35 machine, OVMF UEFI)
make clean        # Remove all build artifacts
make format       # Format all .c and .h files with clang-format
make check        # Static analysis with clang-tidy on all sources
make menuconfig   # Interactive kernel configuration (requires kconfig-frontends)
make gen.clangd   # Generate .clangd from template for LSP support
make disk.img     # Build a demo simplefs disk image
```

Configuration is stored in `.config` (generated by menuconfig) or falls back to `.config-default`. Config is included directly into the Makefile; user-configurable options like `CONFIG_CPU_MAX_COUNT`, `CONFIG_TTY_BUF_SIZE`, and CPU feature toggles are converted to `-D` defines passed to the compiler. Use `make VERBOSE=1` to see full command lines.

**Requirements:** gcc (13.3+), make, qemu-system, xorriso, clang-format, clang-tidy, kconfig-frontends, libncurses-dev.

## Architecture

Uinxed is a Unix-like x86_64 kernel written in C, booted via the [Limine boot protocol](https://github.com/limine-bootloader/limine). It runs as a PIE (Position Independent Executable) loaded at `0xffffffff80000000` (higher half). The memory model uses HHDM (Higher Half Direct Map) provided by Limine.

### Boot Sequence

1. **`boot/limine_request.c`** — Declares all Limine bootloader requests in a special `.limine_requests` ELF section. The linker script (`assets/linker.ld`) places this section first. Entry point `executable_entry()` is set via `limine_entry_point_request`, which tells Limine to jump to `kernel_entry()` after loading.

2. **`init/main.c:kernel_entry()`** — Master initialization sequence in order:
   - CPU feature enable (FPU → SSE → AVX, each gated by Kconfig flags)
   - Memory: frame allocator → paging → kernel heap → Limine modules
   - Video: framebuffer init → `fbcon_init()` for text console
   - Kernel infrastructure: GDT → IDT → ISR registration → ACPI → TSC → SMP
   - Device enumeration: PCI → IDE → serial/parallel → PS/2
   - Filesystem: `init_vfs()` → register tmpfs → register FatFs bridge → mount root
   - `init_cpio()` for initramfs, `devtmpfs_init()` for /dev
   - Finally `enable_intr()` and intentional `panic("No operation.")` (no userspace yet)

### Memory Subsystem (`mem/`)

- **Physical frames:** `frame.c` uses Limine's memory map to build a bitmap-based frame allocator. Frames are marked used/reserved/free in the bitmap. `frame_alloc()`/`frame_free()` manage individual 4K frames; `frame_alloc_pages()` for contiguous multi-frame allocations.
- **Virtual memory:** `page.c` implements 4-level x86_64 paging. Supports 4K, 2M huge pages, and 1G huge pages. `page_map_to()` maps a virtual address to a physical frame in a given page directory. `KERNEL_PTE_FLAGS` = Present + Writable + No-Execute. PAT (Page Attribute Table) is configured via MSR. `page_map_range_to_random()` implements KASLR by mapping virtual ranges to random non-contiguous physical frames.
- **Page walker:** `page_walker.c` provides utilities to traverse page tables level-by-level.
- **Heap:** `heap.c` is the kernel heap allocator (`malloc`/`free`/`calloc`/`realloc`), backed by page allocations. Defined range: `KERNEL_HEAP_START` through `KERNEL_HEAP_START + KERNEL_HEAP_SIZE`.
- **HHDM:** `hhdm.c` handles Higher Half Direct Map — converting between physical and virtual addresses using the offset provided by Limine. `phys_to_virt()` and `virt_to_phys()` are the key conversions.

### VFS Architecture (`fs/`)

The VFS is the central filesystem abstraction. Every filesystem registers a `vfs_callback` struct containing function pointers for all operations (mount, open, close, read, write, mkdir, mkfile, link, symlink, stat, ioctl, dup, poll, free, delete, rename, readlink).

- **Node tree:** `vfs_node_t` forms a hierarchical tree via `parent` pointer and `child` circular linked list. Root directory `rootdir` is created in `init_vfs()`.
- **Path resolution:** `vfs_open()` tokenizes paths on `/`, walks the node tree, and resolves symlinks (up to 16 levels deep). Uses reference counting (`refcount`) to track open handles.
- **Mounting:** `vfs_mount()` tries each registered filesystem in order; `vfs_mount_fs()` targets a specific named filesystem. Mount changes the node's `fsid`, so subsequent operations on that subtree dispatch to the mounted filesystem's callbacks.
- **File types** are bitmask flags: `file_dir`, `file_block`, `file_stream`, `file_symlink`, `file_fbdev`, `file_keyboard`, etc.

**Existing filesystems:**
- `tmpfs.c` — In-memory filesystem, registered with `vfs_regist()`, becomes the initial root.
- `fatfs_vfs.c` — Bridge between VFS callbacks and the FatFS library (FAT12/16/32). Routes vfs operations to FatFS `ff.c` functions.
- `simplefs.c` — Minimal test filesystem for development.
- `devtmpfs.c` — Device tmpfs initialization.
- `cpio.c` — CPIO archive reader for initramfs.

### I/O and Console Architecture

**Writer abstraction** (`include/writer.h`):
```
writer { void *data; write_handler handler; }
```
A lightweight interface for character output. `printk`/`plogk` use `vwprintf()` which writes through a `writer`. The TTY writer (`tty_writer`) routes all characters to the TTY subsystem.

**TTY subsystem** (`drivers/char/tty.c`):
- Selectable output device: VGA framebuffer (`tty0`) or Serial (`ttyS0`–`ttyS3`)
- Controlled by kernel command line `console=...` or compile-time `CONFIG_TTY_DEFAULT_DEV`
- VGA path: Characters are pushed to a ring queue (`TTY_VGA_QUEUE_SIZE` = 8× buffer size), flushed to `fbcon_put_string()` when full or at newlines. A deferred flush mechanism (`tty_deferred_flush()`) handles periodic dirty-region rendering.
- Serial path: Line-buffered, flushed to `write_serial()` on newline or buffer full.
- Buffer size is configurable via `CONFIG_TTY_BUF_SIZE` (default 4096).

**Framebuffer console** (`drivers/video/fbcon.c`):
- 9×16 bitmap font. Manages a character grid (`text_grid`) and color grid (`color_grid`) sized to screen dimensions.
- Dirty-region tracking: `dirty_first_col[]` / `dirty_last_col[]` per row enable incremental redraw. `fbcon_flush_dirty_rows()` only redraws cells that changed.
- Character buffer: Accumulates characters for batch rendering (`char_buffer[256]`).
- Supports cursor movement (`\r`, `\n`, `\t`, `\b`), scrolling, and per-character colors.

### Kernel Infrastructure (`kernel/`)

- **debug/:** `printk` (formatted kernel printf via writer), `plogk` (printk + log to ring buffer), `ringlog` (ring buffer with log_buffer_print), `debug` (dump_stack, panic, assert). Stack dumping uses `-fno-optimize-sibling-calls`.
- **gdt/:** Global Descriptor Table setup.
- **idt/:** Interrupt Descriptor Table, with compiler-specific attributes (`INTERRUPT_BEGIN`/`INTERRUPT_END` macros handle GCC vs Clang differences).
- **interrupt/:** ISR handler registration via `isr_registe_handle()`, empty interrupt stubs.
- **cpu/:** CPUID feature detection, EIS (FPU/SSE/AVX init), SMP initialization via Limine.
- **chipset/:** CMOS RTC, DMA controller, SMBIOS parsing.
- **timer/:** Timer subsystem.

### Drivers (`drivers/`)

- **acpi/:** ACPI table parsing, FACP (FADT) for hardware info.
- **bus/pci.c:** PCI bus enumeration.
- **block/:** Block device abstraction (`blockdev.c`), IDE/PATA driver (`ide.c`).
- **char/:** PS/2 keyboard/mouse (`ps2.c`), command line parsing (`cmdline.c`), TTY.
- **interrupt/apic.c:** Local APIC and I/O APIC initialization and management.
- **timer/:** HPET (`hpet.c`) high-precision timer, TSC (`tsc.c`) timestamp counter.
- **video/:** Framebuffer video (`video.c`) and framebuffer console (`fbcon.c`).
- **ports/:** Serial port (`serial.c`), parallel port (`parallel.c`).
- **sound/:** PC speaker (`speaker.c`).
- **common.c:** x86 I/O port primitives (inb/outb/inw/outw/inl/outl, string I/O), MSR access (rdmsr/wrmsr), MMIO, TLB flush, CR3/RSP/RFLAGS access, atomic load/store, interrupt enable/disable, compiler barrier.

### Libraries (`libs/`)

- **libc/:** Kernel-builtin C library subset — string functions, stdlib (atoi, itoa, memory alloc wrappers), math.
- **glist/:** Data structures — circular linked list, intrusive list, singly linked list. VFS uses circular lists for directory children.
- **gfxs/:** Graphics — BMP image support, bitmap fonts (9×16), graphics processing utilities.
- **data/:** UTF-8 library.
- **sync/:** Spin locks (used by TTY flush, SMP synchronization).
- Pre-built archives: `liballoc-x86_64.a` (allocator), `libelf_parse-x86_64.a` (ELF parsing).

### Code Style

- **Formatting:** clang-format with 4-space indent, `BreakBeforeBraces: Custom` (functions and classes get newline brace, control statements don't), 145 column limit, right-aligned pointers, sorted includes.
- **Static analysis:** clang-tidy with cert, llvm, bugprone, performance, linuxkernel, and clang-analyzer checks enabled.
- **Naming:** snake_case for functions and variables. File names are lowercase with underscores. Header guards use `INCLUDE_XXX_H_` pattern.

### Key Constants

- `KERNEL_BASE_ADDRESS`: `0xffffffff80000000` (higher half)
- `KERNEL_NAME`: "Uinxed", `KERNEL_VERSION`: "0.1.1"
- Page sizes: 4K (`PAGE_4K_SIZE`), 2M (`PAGE_2M_SIZE`), 1G (`PAGE_1G_SIZE`)
- `ERRNO_MASK`: `0x7FFFFFFFFFFFF000` for negative error code convention
- `KERNEL_LOG`: compile-time toggled via `CONFIG_KERNEL_LOG`
